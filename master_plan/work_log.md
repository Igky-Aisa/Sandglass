## 2026-07-22 - Sonnet 5 - Fix: asyncio LimitOverrunError on large stream-json lines

### 1. Context Snapshot
- **Goal**: User hit `✖ Failed: Separator is found, but chunk is longer than limit` running `quotashield execute` and asked what it meant.
- **State**: `quotashield` bumped 0.5.0 → 0.5.1 (bugfix). `claude_client.py`'s subprocess now opens with a 10MB stream buffer instead of asyncio's 64KB default. All 50 tests still pass; verified against a real `claude -p` call.
- **Previous Blocker**: None — this surfaced from the user's own real usage, not something flagged in a prior session.

### 2. Work Done
- **Root cause**: `send_prompt` in `claude_client.py` opens the `claude -p --output-format stream-json` subprocess via `asyncio.create_subprocess_exec` without a `limit=` argument, so its stdout `StreamReader` uses asyncio's default 64KB-per-line buffer. `stream-json` emits one JSON object per line, and under `bypassPermissions` (the default), a tool call that reads or writes a sizeable file can easily produce a single event line — most likely a `tool_result` — over 64KB. When that happens, iterating `proc.stdout` via `async for` raises `asyncio.LimitOverrunError: Separator is found, but chunk is longer than limit` — the reader found the line's trailing newline, the line itself was just too long for the buffer.
- **Fix**: added `STREAM_BUFFER_LIMIT = 10 * 1024 * 1024` and passed `limit=STREAM_BUFFER_LIMIT` to `create_subprocess_exec`, comfortably covering any realistic single-event size. Also wrapped the read loop in `try/except (asyncio.LimitOverrunError, ValueError)` as a defensive fallback: if a line somehow still exceeds even 10MB, the subprocess is explicitly killed and reaped (`proc.kill()` + `await proc.wait()` — previously an uncaught exception here would've left it as an orphaned zombie process) and a clear `RuntimeError` is raised explaining it's a QuotaShield buffer limit, not a quota/auth problem, instead of letting the raw asyncio internal error surface uninterpreted the way the user saw it.
- **Verified for real**: ran a live `quotashield execute` (haiku, cheap prompt) against the actual subscription after the fix — completed normally, confirming the larger buffer doesn't change normal-case behavior. Did not attempt to force a real >64KB single line (would require either an expensive prompt or a contrived large-file tool call) — the fix itself (raising `asyncio.StreamReader`'s `limit`) is the standard, well-documented remedy for this exact asyncio error, so this was treated as low-risk enough not to justify spending extra quota manufacturing a repro.
- Updated `MASTER_ARQ_SYSTEM_MAP.md`'s `ClaudeClient.send_prompt` sketch to document the buffer limit and why; `CHANGELOG.md` got a `[0.5.1]` entry.

### 3. Next Steps (For the next agent / Phase 2)
- 10MB is a generous but arbitrary ceiling — if a genuinely huge tool result ever exceeds it (e.g. reading a very large binary-ish file as text), the new explicit error message will at least make that obvious immediately rather than surfacing as an opaque asyncio traceback, but the underlying prompt would still fail.
